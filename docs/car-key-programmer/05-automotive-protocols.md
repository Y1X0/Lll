# 05 — بروتوكولات السيارات

---

## 1. خريطة الطبقات

```
Application  │ OBD-II (J1979)   │ UDS (ISO 14229)  │ KWP2000 (ISO 14230-3)
Transport    │ ISO-TP (ISO 15765-2)                 │ (تأطير KWP الخاص)
Data Link    │ CAN (ISO 11898-1)                    │ K-Line (ISO 9141-2 / 14230-2)
Physical     │ CAN H/L — Pins 6,14                  │ K-Line — Pin 7
```

---

## 2. دور كل بروتوكول

| البروتوكول | ماذا يفعل | لماذا نحتاجه |
|---|---|---|
| **CAN (ISO 11898)** | ناقل تسلسلي تفاضلي متعدّد الأسياد، تحكيم بالأولوية، 500 kbps للتشخيص | العمود الفقري لكل مركبة بعد ~2008 |
| **ISO-TP (ISO 15765-2)** | ينقل رسائل حتى 4095 بايت عبر إطارات 8 بايت: `SF / FF / CF / FC`، مع `BS` و `STmin` | **بدونه لا يمكن قراءة VIN أو أي بيانات > 7 بايت.** أول ما يُبنى |
| **OBD-II (SAE J1979)** | تشخيص انبعاثات موحّد قانونًا: Modes `01`–`0A` | مصدر VIN (`09 02`)، DTCs، بيانات حيّة — **متاح للجميع ولا يحتاج إذنًا** |
| **UDS (ISO 14229)** | تشخيص المصنّع: `0x10` جلسة، `0x11` إعادة تشغيل، `0x14/0x19` DTC، `0x22/0x2E` قراءة/كتابة DID، `0x27` Security Access، `0x31` روتينات | **قلب التعرّف على المركبة.** نستخدم منه القراءة فقط |
| **KWP2000 (ISO 14230)** | سلف UDS، على K-Line غالبًا؛ تهيئة 5-baud أو Fast Init | ضروري لمركبات ما قبل ~2006 — **مهم جدًا في الأسطول الأردني** |
| **ISO 9141-2** | K-Line أبسط، تهيئة 5-baud | مركبات 1996–2004 |
| **LIN (ISO 17987)** | ناقل سلكي واحد بطيء (~20 kbps) للأطراف: مرايا، مقاعد، بعض هوائيات LF | ⏳ **ليس في MVP** — لا يظهر على موصل OBD عادةً |
| **CAN-FD (ISO 11898-1:2015)** | حمولة حتى 64 بايت، سرعة بيانات أعلى | ⏳ **v2** — يلزم لمركبات 2022+ |
| **DoIP (ISO 13400)** | تشخيص عبر Ethernet | ⏳ **v3** — مركبات فاخرة/حديثة |
| **SAE J2534** | **واجهة برمجية قياسية** تسمح لبرنامج OEM بالتحدّث مع أي واجهة متوافقة | 🔑 **ركيزة استراتيجية — يجعل جهازنا يشغّل Techstream** |

## 3. قرار النطاق

### ✅ في MVP (v1.0)
| البروتوكول | المبرّر |
|---|---|
| CAN 2.0B @ 500 kbps, 11-bit | يغطّي RAV4 XA30+ وكل الأسطول الحديث |
| **ISO-TP** كامل (SF/FF/CF/FC, BS, STmin, padding) | لا شيء يعمل بدونه |
| OBD-II Modes 01, 03, 04, 07, 09 | VIN + DTC + بيانات حيّة |
| UDS: `0x10, 0x11, 0x14, 0x19, 0x22, 0x3E` | التعرّف والبصمة والقراءة |
| UDS `0x27` — **كشف ورفض فقط** | تصنيف الإجراء كـ "يتطلب OEM" |
| K-Line: ISO 9141-2 + ISO 14230 (5-baud + Fast Init) | تغطية RAV4 XA20/XA30 والأسطول القديم |
| **J2534-1 (المجموعة الأساسية)** | تشغيل برنامج OEM عبر جهازنا |

### ⏳ مؤجَّل
| البروتوكول | متى | لماذا التأجيل |
|---|---|---|
| CAN 29-bit ID | v1.1 | نادر في تشخيص الركّاب |
| CAN-FD | v2.0 | يتطلب تبديل MCU إلى STM32G0B1 |
| LIN | v2.0 | قيمة محدودة عبر منفذ OBD |
| DoIP | v3.0 | لا يوجد في السوق المستهدف بعد |
| J2534-2 (الإضافات) | v2.0 | يلزم لبعض برامج OEM المتقدّمة |
| SGW / Secure Gateway (FCA-style) | v2.0 | لا ينطبق على تويوتا حاليًا؛ يلزم لـ Chrysler/Dodge |

## 4. تفاصيل تنفيذية حرجة (أخطاء شائعة تُهدر أسابيع)

| الفخّ | الوصف | الحلّ |
|---|---|---|
| **`STmin` غير محترم** | الوحدة تطلب فاصلًا زمنيًا بين الإطارات المتتالية؛ تجاهله ⇒ فقد بيانات صامت | تنفيذ مؤقّت دقيق بالميكروثانية في الفيرموير، لا في الهاتف |
| **`BlockSize` غير محترم** | إرسال أكثر من BS إطارًا قبل انتظار FC | آلة حالة ISO-TP كاملة، لا تبسيط |
| **Padding** | بعض الوحدات تتطلب حشو الإطار لـ 8 بايت بـ `0x00` أو `0xAA`، وأخرى ترفضه | خاصية لكل ملف تعريف مركبة، ليست ثابتة عالمية |
| **`Tester Present (0x3E)`** | الجلسة الموسّعة تنتهي بعد ~5 ثوانٍ بلا نشاط | مهمة دورية كل 2 ثانية أثناء الجلسة النشطة |
| **`0x78` Response Pending** | الوحدة تردّ "انتظر" — كثيرون يعتبرونه خطأ | إعادة تشغيل المهلة عند كل `0x78`، بحدّ أقصى للمحاولات |
| **Bus-Off على ESP32 TWAI** | علّة معروفة في التعافي التلقائي | آلة حالة برمجية + إعادة تهيئة كاملة للطرفية |
| **إغراق الناقل** | استقصاء عدواني يعطّل وظائف السيارة | حدّ معدّل صارم + Listen-Only افتراضيًا + مهلة بين الاستقصاءات |
| **تهيئة K-Line 5-baud** | توقيت دقيق 200 ms/bit؛ خطأ صغير ⇒ فشل صامت | تنفيذ بـ GPIO مؤقّت بالجهاز، لا بـ UART عادي |

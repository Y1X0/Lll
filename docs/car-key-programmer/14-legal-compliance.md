# 14 — الجانب القانوني والامتثال

> ⚠️ **إخلاء مسؤولية:** هذا تحليل هندسي/تجاري لمخاطر قانونية، **وليس استشارة قانونية.**
> **يجب** الحصول على رأي محامٍ أردني مرخّص قبل أي التزام. الميزانية مخصّصة لذلك في
> [11-cost-model](11-cost-model.md) (بند 1.6).

## 1. هل تصنيع الجهاز قانوني؟

**نعم — بشروط.** التمييز الحاسم:

| نوع الأداة | الوضع القانوني العام |
|---|---|
| **أداة تشخيص** (تقرأ VIN، أعطال، بيانات) | ✅ **قانونية بلا خلاف تقريبًا.** ملايين الوحدات تُباع عالميًا. الحقّ في الإصلاح يدعمها |
| **أداة برمجة مفاتيح تعمل عبر التفويض الرسمي** (J2534 + برنامج OEM) | ✅ **قانونية** — بل هي المسار الذي صمّمه المصنّعون |
| **أداة تتجاوز `Security Access` بخوارزميات مشتقّة عكسيًا** | 🟠 **رمادية إلى محظورة** حسب الولاية القضائية |
| **أداة تُسوَّق كوسيلة لتشغيل مركبة بلا مفتاح المالك** | ❌ **غير قانونية بوضوح** — تسهيل جريمة |

**منتجنا يقع في الفئتين الأولى والثانية بالتصميم المتعمّد.** هذا ليس صدفة — هو القرار المعماري الأهم.

### القوانين ذات الصلة
| الولاية القضائية | الإطار | الأثر |
|---|---|---|
| **الأردن** | قانون العقوبات (تسهيل السرقة) · قانون الجرائم الإلكترونية · حماية المستهلك · قانون الاتصالات (TRC) | لا يوجد قانون خاص بأدوات مفاتيح السيارات `[VERIFY]` — النطاق العام ينطبق |
| **الاتحاد الأوروبي** | Directive 2019/771 · Right to Repair · GDPR · RED 2014/53/EU | يجب امتثال GDPR إن خُدم مستخدمون أوروبيون |
| **أمريكا** | DMCA §1201 (مع **استثناء صيانة المركبات** المتجدّد) · إطار NASTF · قوانين الولايات لترخيص الأقفال | NASTF LSID هو معيار الصناعة الفعلي |
| **الخليج** | تشريعات متفاوتة؛ الإمارات والسعودية أكثر صرامة في الاستيراد | يتطلب تحقّقًا قبل التصدير |

## 2. هل بيع الجهاز قانوني؟

**نعم، مع ضوابط بيع إلزامية:**

| الضابط | التنفيذ |
|---|---|
| **تحقّق من هوية المشتري** | لا بيع مجهول. سجل تجاري أو رخصة مهن أو هوية |
| **البيع للمهنيين فقط** | لا بيع تجزئة للجمهور العام |
| **اتفاقية استخدام موقّعة** | تحظر الاستخدام غير المصرّح به صراحةً |
| **سجل مبيعات كامل** | 7 سنوات، يشمل التسلسلي والمشتري |
| **تفعيل مرتبط بحساب موثّق** | جهاز مسروق/معاد بيعه = جهاز معطّل |
| **قدرة على الإبطال عن بُعد** | عند إساءة استخدام مؤكّدة أو أمر قضائي |
| **التعاون مع الجهات المختصّة** | إجراء موثّق للاستجابة للطلبات القانونية |

> 💡 **نقطة تحوّل ذهنية:** هذه الضوابط ليست عبئًا امتثاليًا — **هي ميزة تنافسية.**
> إن نظّمت الحكومة الأردنية هذا السوق يومًا (وارد جدًا)، ستكون الشركة الوحيدة المستعدّة،
> وسيُحظر المنافس الذي يبيع أدوات مقلّدة بلا سجلّات. **صمّم للتنظيم قبل أن يأتي.**

## 3. القيود المتعلّقة بـ Immobilizer

| النشاط | الوضع |
|---|---|
| قراءة حالة النظام وأعطاله | ✅ آمن |
| تحديد نوع النظام | ✅ آمن |
| تسجيل مفتاح عبر برنامج OEM مرخّص | ✅ آمن — هذا هو المسار المصمَّم |
| **تجاوز `Security Access` بخوارزمية مشتقّة** | 🔴 **مرفوض في منتجنا** |
| قراءة/كتابة EEPROM بفكّ الوحدة | 🔴 **مرفوض في منتجنا** |
| تعطيل الـ Immobilizer نهائيًا | 🔴 **مرفوض قطعًا** — يبطل التأمين ويشكّل جريمة محتملة |
| استخراج/تخمين مفاتيح تشفير | 🔴 **مرفوض قطعًا** |

**هذه القائمة تُدمج في المنتج كقيد تقني**، لا كسياسة نصّية:
راجع قيد قاعدة البيانات `no_self_security_bypass` في [`schema/vehicle_db.sql`](schema/vehicle_db.sql) —
**المخطّط نفسه يرفض تخزين إجراء يتجاوز حماية.**

## 4. مسؤولية الشركة

| الخطر | الاحتمال | التخفيف |
|---|---|---|
| **إتلاف وحدة أثناء العملية** | 🔴 عالٍ | حراسة الجهد · إجراءات `VERIFIED` فقط · **تأمين مسؤولية المنتج (إلزامي)** · حدّ مسؤولية تعاقدي |
| **استخدام الجهاز في سرقة** | 🟡 متوسّط | التوثيق الإلزامي · السجل · التعاون مع الجهات · **عدم امتلاك قدرة تجاوز أصلًا** |
| **بيانات خاطئة تؤدي لخسارة** | 🟡 متوسّط | إفصاح واضح عن درجة اليقين · حالة `UNTESTED` لا تُعرض كقابلة للتنفيذ |
| **تسريب بيانات العملاء** | 🟡 متوسّط | تشفير · تقليل البيانات · **VIN مجزّأ لا خام** · سياسة احتفاظ |
| **مخالفة تنظيمية (راديو/EMC)** | 🟢 منخفض | استخدام وحدة راديو معتمدة مسبقًا · شهادات كاملة |
| **دعوى انتهاك براءة** | 🟢 منخفض | بحث FTO قبل التوسّع · لا نسخ تصاميم منافسين |

### الضوابط الإلزامية
1. **تأمين مسؤولية المنتج** — غير قابل للتفاوض قبل بيع أول وحدة
2. **شروط استخدام تحدّ المسؤولية** بقيمة الجهاز (بحدود ما يسمح به القانون الأردني)
3. **كيان قانوني منفصل** (شركة ذات مسؤولية محدودة)
4. **سياسة استجابة للحوادث** موثّقة ومجرَّبة

## 5. هل نحتاج تراخيص؟

| الترخيص | مطلوب؟ | الجهة (الأردن) |
|---|---|---|
| تسجيل شركة | ✅ نعم | وزارة الصناعة والتجارة والتموين |
| رخصة مهن | ✅ نعم | أمانة عمّان / البلدية |
| **تصديق راديو (BLE/Wi-Fi)** | ✅ نعم | **هيئة تنظيم قطاع الاتصالات (TRC)** |
| مطابقة مواصفات للاستيراد | ✅ محتمل | مؤسسة المواصفات والمقاييس (JSMO) |
| ترخيص خاص بأدوات الأقفال | ❓ `[VERIFY]` | لا وجود لإطار معروف في الأردن — **تحقّق** |
| ترخيص استيراد/تصدير | ✅ للتصدير | دائرة الجمارك |
| تسجيل معالجة بيانات | 🟡 حسب قانون حماية البيانات الشخصية الأردني | `[VERIFY]` |

**للتصدير:** كل سوق له متطلباته (CE للاتحاد الأوروبي، FCC لأمريكا، SASO للسعودية، ECAS للإمارات).

## 6. إثبات ملكية المركبة — التحليل الصريح

**هل نحتاجه قانونيًا؟** في الأردن: `[VERIFY]` — لا يوجد إلزام قانوني معروف صراحةً.
**هل نحتاجه عمليًا؟ نعم، قطعًا.** لثلاثة أسباب:

1. **حماية الشركة** — يثبت حسن النية إن استُخدم الجهاز في جريمة
2. **حماية الفنّي** — أهم حجّة بيع؛ يحميه من الاتهام
3. **استباق التنظيم** — عندما يُنظَّم السوق سنكون جاهزين

**التصميم:** توثيق إلزامي لكل عملية `OEM_PASSTHRU` و `REMOTE_TECH`.
راجع [08-security-authorization](08-security-authorization.md) §2.5.
**النقطة الأقوى:** مطابقة VIN المقروء من ناقل السيارة مع VIN المكتوب على الرخصة — **تحقّق آلي حقيقي.**

## 7. الفرق بين أداة تشخيص وأداة برمجة مفاتيح

| البُعد | أداة تشخيص | أداة برمجة مفاتيح |
|---|---|---|
| الوظيفة | قراءة وتفسير | **الكتابة في وحدات أمنية** |
| الحماية الأمنية | لا تلمسها | **تتجاوزها أو تعمل بتفويض** |
| التنظيم | خفيف؛ يدعمه الحقّ في الإصلاح | ثقيل ومتزايد |
| خطر إساءة الاستخدام | منخفض | **مرتفع** |
| قيود البيع | تجزئة حرّة | مقيّدة أو ممنوعة في بعض الأسواق |
| المسؤولية | محدودة | **مرتفعة** |

### 🎯 التموضع القانوني الدقيق لمنتجنا

```
MIFTAH = أداة تشخيص (فئة قانونية آمنة)
       + منصّة سير عمل وامتثال (برمجية إدارية — بلا خطر)
       + واجهة J2534 (معيار SAE مفتوح — قانوني تمامًا)
       + وسيط لخدمات OEM مرخّصة (وساطة تجارية)

≠ أداة تجاوز أمني
```

> **هذا التموضع ليس تجميلًا لغويًا — هو حقيقة معمارية مفروضة على مستوى قاعدة البيانات والفيرموير.**
> الجهاز **لا يملك القدرة** على تجاوز `Security Access`. لا نمتنع عن ذلك بالسياسة — بل بالتصميم.
> هذه هي الحجّة الدفاعية الوحيدة التي تصمد أمام محكمة.

## 8. الشهادات المطلوبة للعتاد

| الشهادة | السوق | التكلفة التقديرية | ملاحظة |
|---|---|---|---|
| **CE** (EMC + RED + LVD) | الاتحاد الأوروبي | 4,000 – 8,000 | تنخفض كثيرًا باستخدام وحدة راديو معتمدة |
| **FCC** Part 15B + معرّف الوحدة | أمريكا | 2,000 – 4,000 | نفس الملاحظة |
| **UKCA** | بريطانيا | 1,500 – 3,000 | — |
| **RoHS / REACH** | عالمي | 500 – 1,500 | إقرار مورّد |
| **TRC** | الأردن | 800 – 2,000 | `[VERIFY]` |
| **JSMO** | الأردن | 500 – 1,500 | `[VERIFY]` |
| **SASO / ECAS** | السعودية / الإمارات | 1,500 – 4,000 | للتصدير الخليجي |
| **ISO 7637-2 / 16750** | تصنيع (اختياري) | 2,000 – 5,000 | **موصى به بشدّة** لتقليل مخاطر المسؤولية |

**الإجمالي للإطلاق (الأردن + CE + FCC): 9,000 – 18,000 USD**

> 💡 **توفير حاسم:** استخدام وحدة `ESP32-S3-WROOM-1` **المعتمدة مسبقًا** (FCC/CE/IC modular approval)
> يلغي معظم اختبارات الراديو المكلفة ويترك اختبارات EMC للمنتج النهائي فقط.
> **هذا سبب رئيسي لاختيار وحدة جاهزة بدل شريحة عارية.**

## 2. وظيفة كل طبقة — بجملة واحدة

| الطبقة | الوظيفة الجوهرية | لو فشلت؟ |
|---|---|---|
| **L0 Vehicle** | مصدر الحقيقة — تحمي نفسها بـ Security Access | — |
| **L1 OBD Interface** | عزل وحماية كهربائية للطرفين | 🔴 إتلاف وحدات العملاء ⇒ دعاوى |
| **L2 Comm Controller** | تحويل الإشارة التفاضلية إلى إطارات وبالعكس | 🔴 لا اتصال |
| **L3 MCU/Firmware** | حتمية زمنية وضوابط سلامة | 🔴 سلوك غير متوقّع على ناقل حيّ |
| **L4 Security** | ضمان الأصالة والتفويض | 🟠 تقليد + إساءة استخدام |
| **L5 Protocol Core** | فهم البروتوكول + **رفض ما يتجاوز الصلاحية** | 🔴 قراءات خاطئة أو تجاوز غير مقصود |
| **L6 Application** | تحويل البيانات إلى قرار | 🟠 لا قيمة للفنّي |
| **L7a OEM Pass-Thru** | **القدرة الحقيقية على الكتابة — بترخيص** | 🔴 **ينهار المنتج** |
| **L7b Remote** | تغطية ما لا نغطّيه | 🟡 تغطية أضيق |
| **L8 Cloud** | الهوية والتحديث والتوثيق والوساطة | 🟠 توقّف التطوّر |
| **L9 Knowledge Base** | **المعرفة = المنتج الحقيقي** | 🔴 **الجهاز يصبح كأي دونجل بـ 20 دولارًا** |

## 3. أربعة قرارات معمارية تحدّد نجاح المشروع

### ADR-1: الحدّ الأمني مفروض تقنيًا، لا بالسياسة
`L5` تُرجع `RequiresOemAuthorization` عند اكتشاف `0x27`. مخطّط `L9` يمنع تخزين إجراء
`path='SELF'` مع `requires_security_access=true` (قيد `CHECK` في قاعدة البيانات).
**لا يوجد مسار كود يمكن أن يتجاوز حماية — حتى لو أراد مطوّر ذلك.**
**هذه هي حجّتنا القانونية الوحيدة التي تصمد.**

### ADR-2: نواة Rust واحدة عبر كل المنصّات
منطق ISO-TP/UDS يُكتب مرّة ويُستخدم في التطبيق والـ J2534 DLL والاختبار.
**خطأ واحد يُصلَح مرّة — والسلوك متطابق في كل مكان.**

### ADR-3: الجهاز غبيّ عمدًا، والذكاء في التطبيق والسحابة
الفيرموير ينفّذ ولا يقرّر. **يبقى مستقرًّا لسنوات**، بينما تتطوّر المعرفة أسبوعيًا بلا لمس العتاد.
**الجهاز في يد الفنّي لن يحتاج تحديثًا إلا نادرًا — وهذا يقلّل مخاطر التطويب جذريًا.**

### ADR-4: J2534 ليس ميزة إضافية — هو العمود الفقري
كل قدرة كتابة حقيقية تمرّ عبر `L7a`. **إن لم يعمل هذا المسار، لا يوجد منتج.**
لذلك **يجب إثباته في الأسبوع الرابع من المرحلة 0**، بواجهة تجارية جاهزة، **قبل تصميم أي PCB.**

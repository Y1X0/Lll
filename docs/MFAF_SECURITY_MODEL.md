# MFAF — Security Model & Boundaries

## Hard boundaries (enforced by design, not policy)
لا يحتوي النظام ولن يحتوي على آلية غرضها:
- تجاوز lockout أو rate limiting
- تجاوز عتاد المصادقة الآمن أو حدود مصادقة نظام التشغيل
- تجاوز تشفير الجهاز أو أمان الإقلاع أو صندوق التطبيقات الرملي
- فتح شاشة القفل، أو كسر PIN/كلمة مرور لأجهزة حقيقية
- تسليم استغلال، أو سرقة اعتمادات، أو مسح/محو مدمّر

**كيف تُفرَض:** `MockMobileDevice` يحترم الإغلاق ويُبلّغ عنه (لا يتجاوزه حتى مع المدخل
الصحيح)؛ مزوّدو الاقتناء غير المدعومين يُرجعون `ACQUISITION_NOT_AVAILABLE` بدل أي
تجاوز؛ `SafetyBoundaryError` يرفض العمليات على حالة غير اختبارية.

## Input validation (لا تثق بأي قيمة خارجية)
كل: بيانات USB، أسماء الملفات، سلاسل الجهاز، بيانات الأدلّة المستوردة، حقول التقرير —
تمرّ عبر `validation.py`:
- منع Path Traversal (`resolve_within`) — يُرفَض أي مسار يخرج عن الدليل المسموح
- أسماء ملفات آمنة (`safe_filename`) — رفض فواصل المسار ومحارف التحكّم والأسماء الخطرة
- حدود الأحجام (`validate_size`) — سقف افتراضي 8 GiB قابل للضبط
- تعقيم النصوص (`clean_text`) — رفض محارف التحكّم
- معرّفات آمنة (`validate_identifier`)

## Evidence handling
- تجزئة تدفّقية — لا تُحمّل الملفات الكبيرة كاملة في الذاكرة
- صلاحيات صارمة `0o600` للأدلّة، `0o700` للمخزن
- تحقّق سلامة: `VERIFIED / MISMATCH / MISSING / ERROR`
- سلسلة عهدة append-only بربط تجزئة SHA-256 — أي تعديل تاريخي يُكتشَف

## Logging / privacy
- لا كلمات مرور حقيقية — مدخلات اختبار اصطناعية عبر معرّفات فقط
- لا أسرار في السجلّات؛ مخرجات CLI بنيوية بلا اعتمادات
- لا تنفيذ أوامر عبر بيانات الجهاز؛ لا subprocess/shell في المسار الأساسي
- الحقول غير المتاحة تُمثَّل بـ `null` صريح (لا تخمين)

## Not verified
مزوّدو Android/iOS الحقيقيون **NOT VERIFIED — PHYSICAL DEVICE REQUIRED**؛ حاليًا
يُرجعون `NOT_AVAILABLE` بسبب موثّق. لا نتائج عتاد ملفّقة.
